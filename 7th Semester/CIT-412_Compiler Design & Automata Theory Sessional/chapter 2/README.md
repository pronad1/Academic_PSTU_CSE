## Section 2.2 — Syntax Definition

### 1. `sec2_2_grammar_analysis.py` — Derivations & Parse Trees

**Problem:**
Given the classic arithmetic CFG, demonstrate how the string `id + id * id`
is generated by showing (a) the leftmost derivation and (b) the parse tree.

**Grammar used:**
```
E → E + T | T
T → T * F | F
F → ( E ) | id
```

**Key concepts shown:**
- Leftmost derivation — step-by-step rule application
- ASCII parse tree — hierarchical structure of the sentence
- Left-recursion → left-associativity
- Separate non-terminals (E,T,F) → operator precedence

**Embedded input:** `INPUT_STRING = "id + id * id"`

**Sample output:**
```
  [Start          ]  =>  E
  [E → E + T      ]  =>  E + T
  ...
  [F → id         ]  =>  id + id * id

              E
            / | \
           E  +   T
           |     / \
           T    T  *  F
```

### 3. `sec2_2_grammar_design.py` — Grammar Design (Unambiguous CFGs)

**Problem:** Design unambiguous CFGs for four different notations.

**(A) Postfix (RPN) Grammar:**
```
E → E E + | E E - | E E * | E E / | id
```
Stack evaluation: `3 4 2 * +` = 14

**(B) Left-Associative Comma List:**
```
list → list , id | id
```
`a , b , c` groups as `((a , b) , c)`

**(C) Right-Associative Comma List:**
```
list → id , list | id
```
`a , b , c` groups as `(a , (b , c))`

**(D) Arithmetic with Unary Plus/Minus:**
```
E → E + T | E - T | T
T → T * F | T / F | F
F → + F | - F | ( E ) | id
```
Handles: `-3 + 4`, `+3 * -2`, `-(3 + 4)`, etc.

### 4. `sec2_2_divisible_by_3_proof.py` — Advanced Proof

**Problem:** Prove that all binary strings from the grammar `num → "11" | "1001" | num+"0" | num+num` are divisible by 3.

**Method:** Structural induction
- Base: `"11"` = 3, `"1001"` = 9
- Step 1 (num 0): doubles value → `2 × 3k = 3(2k)`
- Step 2 (num num): `3j × 2^n + 3k = 3(j·2^n + k)`

**Embedded input:** `GENERATION_DEPTH = 4`

**Output:**
```
  11       =  3   → YES
  1001     =  9   → YES
  110      =  6   → YES
  ...
  PROOF CONFIRMED: All generated strings are divisible by 3.
```

## Section 2.3 — Syntax-Directed Translation

### 6. `sec2_3_notation_conversion.py` — Notation Conversion SDTs

**Problem:** Write SDT schemes to convert between expression notations.

**Part A — Infix → Prefix (recursive descent SDT):**
```
3 + 4 * 2         →   + 3 * 4 2
( 3 + 4 ) * 2     →   * + 3 4 2
```

**Part B — Postfix → Infix (stack-based SDT):**
```
3 4 2 * +         →   ( 3 + ( 4 * 2 ) )
a b + c d - *     →   ( ( a + b ) * ( c - d ) )
```

**Part C — Postfix → Prefix (stack-based SDT):**
```
3 4 2 * +         →   + 3 * 4 2
a b + c d - *     →   * + a b - c d
```

### 7. `sec2_3_roman_integer_sdt.py` — Integer to/from Roman SDT

**Problem:** Create a complete translation scheme mapping integers to Roman numerals and back.

**Synthesized attribute approach:**
```
integer → thousands hundreds tens ones

   ...
   integer.roman = concat of all fragments
```

**Annotated parse tree example (1994 → MCMXCIV):**
```
  integer ( val = 1994 )
    ├── thousands    .roman = "M"
    ├── hundreds     .roman = "CM"
    ├── tens         .roman = "XC"
    └── ones         .roman = "IV"
```

## Section 2.4 — Parsing

### 9. `sec2_4_recursive_descent_parser.py` — Recursive-Descent Parser

**Problem:** Implement recursive-descent parser functions for arithmetic grammar (after left-recursion elimination).

**Grammar transformation:**

Before (left-recursive — unsuitable):
```
E  → E + T | E - T | T
T  → T * F | T / F | F
F  → ( E ) | num
```

After (suitable for recursive descent):
```
E   →  T E'
E'  →  + T E'  |  - T E'  |  ε
T   →  F T'
T'  →  * F T'  |  / F T'  |  ε
F   →  ( E )   |  num
```

**One Python function per non-terminal:**
`_parse_E()`, `_parse_Eprime()`, `_parse_T()`, `_parse_Tprime()`, `_parse_F()`

**Test results:**
```
  3 + 4                 →  7   ✓
  10 - 3 * 2            →  4   ✓
  ( 10 - 3 ) * 2        →  14  ✓
  ( 2 + 3 ) * ( 4 - 1 ) →  15  ✓
```

Also prints a full **call trace** showing every function call and match.

## Section 2.5 — A Translator for Simple Expressions

### 10. `sec2_5_infix_to_postfix_translator.py` — Complete Mini-Compiler

**Problem:** Build a working translator from infix to postfix (Section 2.5 of Dragon Book).

**Pipeline:**
```
Input String → Lexer → Token Stream → Parser + SDT → Postfix Output
```

**Components:**
- `Lexer` class: tokenises numbers, identifiers, operators, parentheses
- `InfixToPostfixTranslator` class: recursive-descent parser with emit() semantic actions

**Grammar with semantic actions:**
```
rest_expr → + term { emit('+') } rest_expr
          | - term { emit('-') } rest_expr
          | ε
factor    → num { emit(num) }
          | id  { emit(id) }
```

**Translation results:**
```
  Infix Expression               Postfix Output
  9 - 5 + 2                      9 5 - 2 +
  9 - 5 * 2                      9 5 2 * -
  ( 9 - 5 ) * 2                  9 5 - 2 *
  ( a + b ) * ( c - d )          a b + c d - *
```

## Section 2.7 — Symbol Tables

### 11. `sec2_7_symbol_table.py` — Symbol Table with Linked Scopes

**Problem:** Implement linked symbol table scopes to handle nested blocks and variable declarations.

**Data structure:** Stack of dictionaries (each = one scope)
```
scope_stack[-1]  ← innermost (current)
scope_stack[0]   ← global
```

**Operations:**
| Method | Action |
|--------|--------|
| `enter_scope()` | Push new empty scope |
| `exit_scope()` | Pop scope (all its symbols lost) |
| `declare(name, type)` | Add to current scope |
| `lookup(name)` | Search inner→outer until found or fail |

**Simulated program:**
```c
int x = 10; float y;        // global (scope 0)
{
    int a = 5;
    float x = 3.14;         // shadows global x
    {
        char b = 'Z';
        // lookup x → finds float x (scope 1), NOT global!
    }
    // b is gone after inner block exits
}
// a is gone; x reverts to global int x = 10
```

## Section 2.8 — Intermediate Code Generation

### 12. `sec2_8_intermediate_code_gen.py` — AST + 3-Address Code + Control Flow

**Problem:** Three sub-problems combined in one file.

**Part A — AST Construction:**

Node creation functions (`make_binop`, `make_assign`, `make_var`, `make_num`) build a tree:
```
  x = a + b * c
  └── ASSIGN 'x'
      └── BINOP '+'
          ├── VAR 'a'
          └── BINOP '*'
              ├── VAR 'b'
              └── VAR 'c'
```

**Part B — Three-Address Code:**
```
  x = a + b * c         →    t1 = b * c
                              t2 = a + t1
                              x  = t2

  y = (a-b) * (c+d)     →    t1 = a - b
                              t2 = c + d
                              t3 = t1 * t2
                              y  = t3
```

**Part C — Control Flow (labels + jumps):**

While loop:
```
  L1:
    ifFalse x < 10 goto L2
    x = x + 1
    goto L1
  L2:
```

If-else:
```
  ifFalse a > b goto L3
  max = a
  goto L4
  L3:
  max = b
  L4:
```
